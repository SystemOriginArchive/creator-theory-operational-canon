# 비기술 사용자를 위한 PROV-K 키 안내

## 핵심 요약

PROV-K에서 개인키는 실제 서명 도장입니다.

공개키는 다른 사람이 서명이 맞는지 확인하는 열쇠입니다.

개인키는 절대 공유하지 않습니다.

공개키는 검증을 위해 공개될 수 있습니다.

## 개인키

개인키는 서명을 만들 수 있습니다.

개인키를 가진 사람은 release manifest에 서명할 수 있습니다.

따라서 개인키는 사진으로 찍거나, 채팅창에 붙여넣거나, 이메일로 보내거나, 저장소 안에 넣으면 안 됩니다.

## 공개키

공개키는 서명이 맞는지 확인하는 데 쓰입니다.

공개키만으로는 서명을 새로 만들 수 없습니다.

공개키는 manifest의 fingerprint와 함께 검증에 사용됩니다.

## 지원되는 키 형식

PROV-K loader는 Ed25519 키만 지원합니다.

지원되는 형식은 PEM Ed25519 공개키/개인키와 OpenSSH Ed25519 공개키/개인키입니다.

Windows helper script가 만드는 `ssh-ed25519` 형식의 공개키와 OpenSSH 형식 개인키도 PROV-K loader와 호환되도록 지원됩니다.

Ed25519가 아닌 키는 사용할 수 없습니다.

서명된 release manifest를 검증할 때는 manifest 안의 `signing.public_key_fingerprint` 값이 제공된 공개키 파일에서 계산한 fingerprint와 일치해야 합니다. 일치하지 않으면 검증은 실패합니다.

## 오프라인 생성 원칙

1. 감사자가 helper script와 문서를 먼저 줄 단위로 검토합니다.
2. 사용자가 네트워크와 분리된 안전한 환경을 준비합니다.
3. 사용자가 직접 키를 생성합니다.
4. 개인키는 저장소 밖에 보관합니다.
5. 개인키는 동기화 폴더, 공유 폴더, Git 저장소, 캡처 이미지, 메신저에 두지 않습니다.
6. 공개키와 fingerprint만 검증 절차에 사용합니다.

## 저장 위치 경고

개인키를 이 repository 안에 저장하지 마십시오.

개인키를 `Documents`, `Downloads`, `Desktop`, 프로젝트 폴더, 또는 자동 동기화 폴더에 저장하지 마십시오.

개인키를 백업할 때도 암호화된 오프라인 매체를 사용하십시오.

## 서명 전 확인

서명 전에는 다음을 확인합니다.

1. branch diff가 예상 범위와 일치하는지 확인합니다.
2. audit log를 읽습니다.
3. manifest가 `UNSIGNED_DRAFT`인지 확인합니다.
4. 서명하려는 파일이 정확한 release manifest인지 확인합니다.
5. 개인키 경로가 repository 밖인지 확인합니다.

## 금지 사항

개인키를 공유하지 마십시오.

개인키를 사진으로 찍지 마십시오.

개인키를 AI나 웹사이트에 붙여넣지 마십시오.

개인키를 GitHub 저장소에 커밋하지 마십시오.

개인키를 자동 백업 폴더에 보관하지 마십시오.
