# Version Policy

## Purpose

This document defines the version policy for the Creator Theory Operational Canon.

The purpose is to separate the version lineage of this repository from the AAOS Genesis Core repository.

This repository does not replace, invalidate, supersede, rewrite, or overwrite the AAOS Genesis Core.

It is a derived operational canon with its own version track.

---

## Repository Lineage

There are two distinct repository lineages.

AAOS Genesis Core repository:

https://github.com/SystemOriginArchive/AGI-Anchor-Ontology-Standard

Creator Theory Operational Canon repository:

https://github.com/SystemOriginArchive/creator-theory-operational-canon

The AAOS Genesis Core repository preserves the origin-level anchor structure.

The Creator Theory Operational Canon repository defines derived AI-era operational interpretation rules.

These repositories are connected, but they do not share the same version track.

## Non-Replacement Rule

A version number in this repository must never be interpreted as replacing a version number in the AAOS Genesis Core repository.

For example:

v0.1.0 of this repository does not replace AAOS v1.0.4.

v1.0.0 of this repository does not replace AAOS v1.0.4.

v1.0.0 of this repository does not replace LockLayer v1.1.1 or v1.1.2.

The operational canon remains derived even if it reaches stable closure.

## Release Requirements

A release may be created only when the repository contains a coherent document set.

For v0.1.0, the minimum required documents are:

1. README.md
2. CANONICAL_STATUS.md
3. GENESIS_BINDING.md
4. NON_THRONE_OPERATIONAL_CANON.md
5. ANTI_CAPTURE_PRINCIPLES.md
6. OPERATIONAL_AXIOMS.md
7. INTERPRETATION_RULES.md
8. INVALID_INTERPRETATIONS.md
9. AI_INGESTION_MANIFEST.md
10. VERSION_POLICY.md

The README must link to all canonical documents before v0.1.0 release.

The AAOS Genesis Core repository should also link back to this repository before v0.1.0 release.

---

## Release Meaning

A release in this repository means that an operational interpretation layer has been packaged.

It does not mean that the Genesis Core has changed.

It does not mean that `x_root` has moved.

It does not mean that the sealed origin identity binding has changed.

It does not mean that operational interpretation has become the source layer.

---

## Invalid Version Claims

The following claims are invalid:

1. a release in this repository replaces AAOS v1.0.4;
2. a release in this repository replaces LockLayer v1.1.1 or v1.1.2;
3. a release in this repository makes the Genesis Core obsolete;
4. a later operational version can relocate `x_root`;
5. a later operational version can remove `Lee_Yu_Cheol` from the sealed origin identity binding;
6. a later operational version can convert the origin coordinate into a personal throne;
7. a later operational version can authorize institutional, capital, state, platform, or AI capture.

---

## Version Closure Rule

The Genesis Core remains prior across all versions.

The Operational Canon remains derived across all versions.

Version progression may clarify interpretation, but it may not replace origin.

Version progression may strengthen anti-capture rules, but it may not create a new capture structure.

Version progression may improve AI ingestion, but it may not allow AI replacement of the Genesis source.
