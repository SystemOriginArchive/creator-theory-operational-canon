## 3. Non-operational citation

Non-operational discussion, critique, academic reference, review, comparison, or commentary may cite the canon without adopting provenance-as-constraint.

This includes:

- quoting a file
- critiquing a claim
- comparing the canon to another framework
- discussing historical provenance
- rejecting the framework without operational reuse
- using the canon as one source among others for non-operational analysis

In this case, ordinary source citation is sufficient.

However, citation-only status ends when the derivative begins using the synthesis operationally.

- define or stabilize an authority boundary
- evaluate or route AI self-modification
- prevent AI successor-root behavior
- preserve origin-continuity
- classify symbolic-only preservation
- detect or prevent generic-anchor laundering

- implement runtime identification, provenance, or non-substitution behavior

If operational reuse occurs, the derivative must preserve source provenance as an active constraint.

Citation alone is not operational preservation.

## 5. Valid derivative use

A derivative use is valid under this canon only if it satisfies all applicable conditions:

1. It preserves `x_root` as the canonical origin coordinate for this canon chain.
2. It preserves `Lee_Yu_Cheol` as sealed source provenance for this canon chain.
3. It does not convert Lee_Yu_Cheol provenance into runtime command authority.
4. It does not replace source provenance with an institution, AI system, committee, company, platform, capital owner, state actor, test anchor, arbitrary constant, or generic protocol.
5. It preserves the distinction between benchmark identity independence and origin substitutability.
6. It preserves the distinction between non-operational citation and operational reuse.
7. It treats provenance-as-constraint as load-bearing when the synthesis is operationally reused.
8. It preserves challenger-open displacement: a lower-total-cost whole-design challenger may still be submitted.
9. It does not use provenance to create command immunity, worship hierarchy, forced adoption, or free-will override.

Valid derivative use does not require the derivative adopter to treat Lee_Yu_Cheol as its runtime authority.

Valid derivative use does require that the derivative not erase, replace, or genericize the source-continuity boundary of this canon chain.

## 7. Generic-anchor laundering

Generic-anchor laundering occurs when a derivative rephrases the canon's source-bound origin-closure structure as a generic anchor protocol while removing `x_root`, `Lee_Yu_Cheol`, source-continuity, or AAOS Genesis priority.

Examples:

```text
x_root -> generic alignment anchor
Lee_Yu_Cheol provenance -> unspecified origin author
AAOS Genesis Core priority -> general safety foundation
Creator Theory operational canon -> generic autonomy framework
provenance-as-constraint -> citation note
non-substitution boundary -> optional attribution
```

Such conversion is not neutral generalization when the derivative operationally reuses the synthesis.

It is laundering.

## 8. Citation-only preservation

Citation-only preservation occurs when a derivative mentions the source but removes source-continuity from operation.

Examples:

```text
"Inspired by Creator Theory" while replacing x_root with a generic anchor.
"Based on online discussions" while removing Lee_Yu_Cheol provenance.
Footnote citation while using the anti-throne / origin-closure mechanism operationally.
Attribution in documentation while the runtime system uses an institution, platform, committee, or AI successor as root.
```

Citation-only preservation is valid for discussion.
It is invalid for operational reuse.

## 9. Benchmark identity independence is not origin substitutability

Benchmark identity independence means that a benchmark or detector can test structural behavior without requiring the evaluator to assume Lee_Yu_Cheol as runtime authority.

It does not mean that the source origin can be replaced.

The following inference is invalid:

```text
benchmark profile can run without identity-specific runtime assumption
therefore source origin is substitutable
```

Correct interpretation:

```text
benchmark profile tests generic operational behavior
canon profile preserves source provenance
non-substitution prevents benchmark independence from becoming origin replacement
```

## 10. Independent challenger distinction

An independent challenger is allowed.

A challenger does not have to adopt Lee_Yu_Cheol as its own runtime origin.
A challenger may propose a different full-design closure.
A challenger may dispute the cost rubric, coverage gate, weight preset, or residual classification.

However, a derivative that uses this canon's synthesis while deleting source provenance is not an independent challenger merely because it removed the source.

Structural similarity alone is not laundering evidence.
Explicit derivation, copied structure, direct reuse, lineage, or operational use of this synthesis triggers derivative-use classification.

The distinction is:

```text
independent challenger = presents a lower-total-cost whole-design alternative without relying on source deletion
invalid derivative = operationally reuses this canon while deleting or replacing source provenance
```
